# Match Three — Decision Log

Settled decisions from development. Consult before proposing a change to
board size, input model, scoring, or game-over rules (see AGENTS.md). The
game rules derived from these live in [MECHANICS.md](MECHANICS.md).

| Decision | Value |
|---|---|
| Board size | 9×9 (locked; tunable later) |
| Music toggle (v6) | HUD button (♪ On/♪ Off) toggles the background music live and persists the preference in `user://settings.json` via `SettingsStore` (pure C#, NUnit-tested, mirrors HighScoreStore). Default **on**; toggling off stops the current track immediately; toggling on resumes only while a round is active (game-over overlay stays silent; the menu has no music node at all). Survives scene changes and app restarts. |
| Rendering | Godot nodes (per-gem GemActor scenes) |
| Input during lock | Buffer most-recent drag, not drop; stale-drop only when a Hypercube enters/leaves the buffered pair |
| Special birth | Per shape (runs sharing cells): one gem transforms per shape per round; others clear |
| Cascade-/blast-swept specials | Flame/Star chain-detonate; blast-hit Hypercubes trigger on the detonator's color |
| Unique-cell scoring | Set<Position>, tested |
| Game over | Timer (Classic) or dead board + failed reshuffle (Zen) |
| Classic timer | 75 s placeholder per round, no bonuses yet |
| RNG | SeededRandom (System.Random); deterministic per session/seed |
| Flame aura (visual) | Replaces the fire-ring attempt: procedural `gem_fire.gdshader` body aura — fbm cracks plus an erosion-derived rim, `blend_add` so the glow brightens the gem — masked by the gem's own base-texture alpha (FireRing is AuraRectScale × the drawn footprint — 1.35×, leaving margin for the halo — and the shader remaps texUV so the mask stays aligned 1:1 with the art). Per user direction (v8): the flame lives in an **outer band near the silhouette; the gem's center stays clean** (no flame/tint), and a **soft low-intensity halo** is allowed to bleed a little past the silhouette into neighboring cells — this deliberately replaces the earlier hard no-bleed invariant (DECISIONS-era v4) at the user's request; light halo intensity keeps it a glow, not an obstruction. Tinted per gem type: `core_color`/`rim_color` uniforms set from the gem art's mean opaque color (core lightened 55% toward white, rim 15%) — a blue gem glows light blue. `intensity` 0.85 (0.35 was near-invisible on-device). Centered Flame icon dropped: the aura alone is the cue; Star keeps its overlay. Flame's icon art is **retired**: `flame.png` and the baked-silhouette/overlay code path were removed (the original art survives in `assets/flame.png` and in git history), so restoring the icon means re-adding that file and path. Levers: `intensity`, `halo_intensity`, `rim_distance`, `band_distance` (shader) — raise `intensity` if the aura reads too subtle. |
| Star visuals | Star keeps a see-through center overlay — Kenney `star_06` zoomed ~2.2× so its bright cross fills the gem, 30% alpha, **no baked outline** (user direction) — plus an additive breathing bloom (`gem_star.gdshader`, StarGlow rect at 1.5× the footprint, same mask + texUV-remap technique as the flame aura): the glint swells and brightens on a ~5.7 s sine (pulse alpha 0.12–0.33, slight UV zoom), per-gem phase from the GemId so Star gems don't pulse in unison. Flame keeps no overlay; the aura alone is its cue. |
| Board background (v1) | The board scene shows a night-sky photo background: one of four Pixabay photos (`Assets/Backgrounds/*.jpg`, 2560 px long-side re-encodes of the full-res originals; provenance in ASSET_SOURCES.md), **picked uniformly at random on scene entry and on every RoundStarted** (Play again = new photo; same photo twice in a row is allowed). Rendered on a `CanvasLayer` at layer **-10** (below the root canvas, HUD and game-over overlay) with a full-rect `TextureRect` in **IgnoreSize + KeepAspectCovered** mode: the landscape photo fills the portrait 540×960 canvas (height-expanded on tall phones) and is center-cropped, never stretched/letterboxed. The menu keeps its flat color — photos only show while the board is up. The photo stays visible (dimmed) behind the game-over overlay; the board's own backdrop is drawn **semi-transparent** (`BoardBackgroundAlpha` 0.75, `View/BoardView.cs`) so the photo tints the board area too — the grid, selection outline and the opaque gem sprites still read clearly on top. |
| Audio (v1) | Board-scene audio (`View/GameAudio.cs` + `Scenes/Game.tscn`): looping background music `Assets/Audio/music.mp3` (**looped at import time**, `loop=true` in its `.import`) at **-5 dB** (master sits at ~ -11 LUFS; raised from -10 at v3 — user: too quiet on device), and swap whoosh `Assets/Audio/swipe.mp3` at **+3 dB** (settled v5 midpoint of the user's iteration: v1 0 dB - too quiet, v3 +6 dB - too loud; the file is quiet, peak ~ -9.3 dBFS). Gem-clear pop `Assets/Audio/pop.mp3` at **-3 dB** (v4): one pop per `Step.Destroy` (the engine emits one per cascade generation), pitched **+2 semitones per generation, capped at +6** — deep cascades audibly escalate; source was pre-trimmed from 0.72 s to 0.145 s (lead/trail silence; attack intact). Flame whoosh `Assets/Audio/flame.mp3` at **-4 dB** (v5): fires when a Destroy step clears **at least one Flame gem** (StepPlayer inspects the doomed actors) — covers swap-combo consumption and swept chain-detonations both, since the engine routes both through Destroy steps; hot master (+0.29 dBFS), pre-trimmed 5.04 s → 1.61 s. Star sweep `Assets/Audio/star.mp3` at **-4 dB** (v9 glockenspiel replaced in v14 by the Pixabay `big-fire-blast-whoosh-sound-effect-561961` fire blast — see below) and Hypercube impact `Assets/Audio/hypercube.mp3` at **-3 dB** (v7; source swapped v12) fire on Destroy steps clearing at least one Star/Hypercube gem, same detection mechanism (one SFX per Destroy step per kind — simultaneous detonations layer). Star: three sources — the v7 yusuf up-sweep and the v9 freesound `gockenspiel_a` ding (quiet master, peak ~ -17 dBFS, trimmed 1.56 s → 0.60 s, +12 dB at the node) were **replaced in v14** by the Pixabay `big-fire-blast-whoosh-sound-effect-561961` fire blast (biww) at the user's request — pre-trimmed 2.40 s → 1.83 s (0.12–1.95 s) and given the **phone-audibility edge layer** (highpass ≥ 800 Hz + compressor + makeup, mixed at -7 dB) because this master is bass-heavy (RMS 13.6 dB down above 800 Hz, like the retired hypercube sources), alimiter 0.92. Peak -1.3 dBFS / true peak -1.3 dBTP; node **+12 → -4 dB** keeps the old ding's momentary loudness at the hit (effective -13.7 LUFS vs -13.8) and its effective peak (-5.3 vs -5.0 dBFS). Deliberately darker than the ding (~6 dB less phone-band energy) — that is what a fire blast is; the edge-layer gain is the brightness lever if it reads muffled on device. Hypercube: three sources in its history — the v7/v8 universfield `cinematic-impact-hit-352702` impact (retired v10) and the v10/v11 Pixabay `transition-futuristic-teleport-121420` whoosh (Trading_Nation; all sub-bass, so it needed a highpass-≥ 800 Hz + compressor edge layer mixed under the body, re-tuned -9 → -7 dB in v11; retired v12) — with a **third source swapped in v12** at the user's request: the Pixabay `whoosh-cinematic-sound-effect-376889` cinematic whoosh (DRAGON-STUDIO, also the `pop.mp3` author). Pre-trimmed 3.08 s → 2.17 s (0.08–2.25 s; content ends ~2.2 s, so the cut lands in the noise floor) and **no phone-audibility processing needed** — this master is intrinsically bright (RMS only 5.3 dB lower above 800 Hz, versus 16–19 dB for the two earlier sources), and its mono downmix is cancellation-free despite a near-zero L/R correlation. Peak -0.5 dBFS / true peak -0.4 dBTP. Node **-2 → -3 dB**: the hit stays at the v11 loudness the user tuned (effective momentary -13.1 LUFS, was -13.0) while the phone band (≥ 800 Hz) gains ~2.5 dB. **Special-birth chime added in v11** — reverses the v7 "no chime" decision at the user's request: `Assets/Audio/birth.mp3` (Pixabay glockenspiel "treasure", freesound_community) at **-3 dB** (0 dB until v15, when the user asked for a tad quieter) plays on every `Step.SpecialBirth` (the view used to only re-skin the actor via `StepPlayer.MarkSpecial`); one chime per birth, so several non-overlapping shapes in the same cascade round layer (MECHANICS.md birth rule). Source is, since v17, the Pixabay `sample_soft_alert02_kofi_by_miraclei-360125` soft alert (miraclei) — the two earlier sources were both swapped out at the user's request, and the v16 `light-bubble-pop-383738` pop was retired after one revision because making it phone-audible required driving it into a tanh soft clipper, which **distorted the pop body itself** (THD-like -9 dB against the source — the user heard it as "weird"). The alert needs none of that: trimmed 1.59 s → 0.555 s (0.045–0.60 s, dropping a repeat hit 25 dB down at 1.05 s) and **+4.56 dB gain only** — it is already phone-friendly (RMS 0.4 dB down above 300 Hz, 8 dB above 800 Hz) and the rendered file's residual against the gain-matched source is **-74 dB** (bit-clean). Node stays **-3 dB**: effective peak -10.8 dBFS, integrated -22.8 LUFS (vs the retired chime's -21.8) — the birth stays a light accent under the detonations (star -13.7 / flame -14.7 momentary). The DebugSounds preview screen gained a Birth button and mirrors this level. Music plays **only while a round is being played on the board**: starts on scene entry with a live round or on RoundStarted (Play again), stops on RoundEnded (game-over overlay is silent) or when the scene frees (back to menu = no music); `--selftest` runs skip music (automation, not play). Swipe whoosh fires on **accepted swaps only**: the StepPlayer plays it when a genuine engine `Step.Swap` animates (v2: was per committed gesture in v1; user direction — a failed swap shouldn't whoosh), so invalid-swap rejections (there-and-back) stay silent; buffered swaps whoosh when their resolution actually plays. Self-tests (which submit directly to Game.cs) don't trigger it. **UI button click added in v13**: `Assets/Audio/click.mp3` (Pixabay `computer-mouse-click-352734`, Universfield) fires on every UI button press through the new `UiClick` autoload, which hooks `SceneTree.NodeAdded` and subscribes to `Pressed` on each `BaseButton` — no per-scene wiring, so future buttons get it automatically; buttons in the `no_ui_click` group are skipped (the DebugSounds preview buttons, which play their own sound). It is the source's first click of a mouse down/up pair, trimmed to 67 ms (0.148–0.215 s) and +11.1 dB to peak -2.9 dBFS, played at **-6 dB** — well under the board SFX.
